# Force Curve Lab — notes for Claude

Static teaching site (GitHub Pages). Vanilla ES modules. **No build step, no npm dependencies, no CDNs.** Keep it that way so it loads fast on phones.

## Layout
- `index.html`, `css/style.css`: one page; light and dark mode via CSS variables (header switch: auto/light/dark), layout switch (auto/side by side/stacked; wide screens keep the figure beside the curves), foldable sections on narrow screens, a floating control bar once the slider scrolls away, charts that scrub on tap/drag
- `js/physics.js`: pure statics for single-joint exercises (`pose`, `loadForce`, `limbWeights`, `analyze`, `sampleCurve`). No DOM. Imported by the tests. Every exercise is a two-segment chain (base → mid → tip); `analyze` returns `jointTorque` (= `loadTorque` + `limbTorque`) about the moving joint, positive when it resists the lift. Load types: gravity, cable, machine (cam), reaction (closed chain), band. A variant's `strengthScale` (factor or points) corrects strength for posture or grip.
- `js/multijoint.js`: multi-joint lifts. A solver per lift family turns the driver value into a posture (balance, rail, bar path, contacts), then `jointTorque` sums the moments on one side of each joint. Side-view solvers: `standing` (squat / hinge / deadlift / bent-over row via `load: "row"`), `split`, `hipThrust`, `seatedRow`; holds: `plank` (front and side plank: the body as a beam on two supports, driver = support height) and `pallof` (top view, driver = reach). `analyzeMulti` applies strength curves, a joint's `negative` curve for the opposite direction, and `jointScale` corrections (variant- or exercise-level). Shared anthropometry in `data/body.json`
- `js/multijoint3d.js`: 3D statics (vectors, joint moments split into anatomical components). Solvers: `legPress3d`, `squat3d`, `hinge3d` (RDL), `split3d`, `hipThrust3d` (legs share `legFromFloor`); `bench3d`, `press3d`, `row3d`, `pull3d` (arms). Right limb analysed, left mirrored. Forces statics can't decide (sideways floor push, bar spread) use static optimisation (`leastEffort`) or a visible slider, never a hidden guess. `jointScaleAt`: posture corrections by factor, points (own or another joint's angle via `by`, one torque `direction`), or a shoulder × elbow `grid`.
- `js/view3d.js`: hand-rolled orthographic 3D view in SVG with drag-to-turn and camera presets
- `js/chain3d.js`: 3D figure for single-joint exercises with `figure3d: {kind: "chain", base, plane, both, start, yawKey, cam}`: the 2D chain placed in its plane (frontal / sagittal / transverse) at the shoulder or knee of a standing body, turned so the variant's gravity points down (lying, inclined). Display only; the statics stay 2D. A "2D" button switches back to the flat figure; a variant's `oneSided` leaves the other limb at rest
- `js/trunk3d.js`: 3D trunk view for the core exercises (`trunk3d.map` in their JSON: exercise muscle → lumbar model groups, `"group"` both sides or `"group:r"`/`"group:l"`): every fascicle of the OpenSim lumbar spine model (`data/opensim/lumbar-muscles.json`, Christophy et al. 2012, MIT licence; written by `tools/lumbar_export.py`) shaded by activation. Display only: upright (crunch, leg raise, Pallof press); `trunk3d.pose: "body"` sets it straight on the solver's body (planks; `bodyFrame` handles side-view and front-view results, the side plank lying on its left side); `"lumbar"` (back extension) also bends it to the solver's lower-back angle (`posedTrunk` blends the exported flexion postures, `data.posed`) and set on its pelvis, the rest of the body drawn from the 2D result (solver `draw` items flagged `trunk` become a see-through outline)
- `js/bodymap-extra.js`: body-map overlays for muscles wger's map lacks (erector spinae, gluteus medius, rotator cuff, forearm ...): own shapes in wger's 200 × 369 frame; `MAP_BY_ID` muscle id → overlays. A test checks every drawn muscle lights something
- `js/hipmodel.js`: hip muscle model for the single-joint hip abduction / adduction (`hipModel` in their JSON; `figure3d: "hip"` gives them the 3D figure): moment arms from the OpenSim geometry in `data/opensim/hip-muscles.json` (cylinder wrapping), posture with the seated trunk lean (`hip` in the variant), static optimisation over all hip muscles (three moments; `hip.balance` drops those a support carries), and the 3D scene. Muscles with driver `hipModel` list their model parts in `osim`
- `js/muscles.js`: activation estimate from the physics result (a muscle may follow several joint components via `joints`, each optionally scaled by `jointScale`, e.g. the lats with the elbow in pulls; see docs/model-limits.md, EMG section)
- `js/figure.js`, `js/chart.js`: hand-rolled SVG rendering. The figure draws `postures` and muscle `draw` specs from the JSON, rotated so the variant's gravity points down; insets in its top corner: the feet turned in or out (calf raise), a machine's cam turning with the lever (`camInset`, from `camProfile`)
- `js/finger.js`, `js/edgefig.js`: the edge lift (`"model": "finger"`): finger statics (FDP from the DIP moment, FDS from the PIP, MCP leftover, A2/A4 pulley loads), the four-finger set (`fingerSet`: reach search over the edge position, hand tilt and roll; least-effort split with the quadriga link), `analyzeEdge` / `sampleEdge` for the page, `liftProfile` for Play (force over one lift, m·(g + a)), and the Fingers / Hand / Arm figures. `analyzeFinger` (one index finger) stays for the Vigouroux check in the tests. Variant `params` hold the grip posture; `placement` sliders the pressure point, edge shape (a four-bar widget), quadriga link, arm angles and lift-off time
- `js/pinchlift.js`, `js/pincer.js`, `js/pinchfig.js`: the pinch lift (`"model": "pinch"`): squeeze from friction (μ·N0·(N/N0)^n per contact patch, equal squeeze on both faces), capacity from a measured maximal pinch × strength × wrist factor, and the thumb–index pincer model (pliers / jointed, ARMS moment arms at measured postures in `data/opensim/arms-pincer.json`, non-commercial) scaled per width to fail at that capacity; the front-view figure
- `tools/arms_hand_export.py`: ARMS bones and muscle paths for the 3D hands (edge lift: three grips; with a third argument, the poses in that JSON: the pinch lift's widths → `data/opensim/arms-pinch-hand.json`, non-commercial). `tools/arms_pinch_oppose.py`: an experiment, not used (see docs/model-limits.md)
- `tools/pinch-table.mjs`: precomputes the whole-hand pinch maximum (`data/opensim/pinch-whole.json`, non-commercial) so the page never searches for it live (that stalled the browser). Rerun after any change to `pincer.js`, `finger.js` or their data; a test fails when the table is stale
- `tools/arms_posture_arms.py`: exports ARMS moment arms and muscle forces at given postures (OpenSim, run locally); `tools/angle-picker.html`: offline helper that measures joint angles on photos or video frames (not part of the site)
- `js/regions.js`, `data/regions/*.json`: close-ups of one body region (schematic, each muscle a belly + tendons, coloured by activation). A muscle joins a close-up via `region`; `regionPath` names the drawn muscle(s) it colours (one id or a list). A list means the model only knows the group: each head gets the group's value, hatched. Drawn muscles are spindles (`from`/`to`/`belly`/`w`) or outlines (`d` + `label`)
- `js/wger.js`: optional wger.de API calls; must fail silently. The muscle-map SVGs are copied in `assets/wger/` (CC-BY-SA, keep the attribution)
- `data/exercises/*.json`: all exercise content (chain, variants, strength curve, muscles, postures, phases, `placement` sliders)
- `data/references.json`: every paper cited in a `source` field, shown in the app's References section
- `docs/model-limits.md`: what the model approximates, per lift, and how each was checked against measurements; `docs/reading-list.md`: papers still to get; `docs/model.html`: per-exercise "How the model works" page, built from the exercise JSON (linked from each exercise); `docs/edge-lift-model.html`: the edge lift's own write-up
- `tools/osim-hip.mjs`: reads an OpenSim `.osim` file (Rajagopal model, kept outside the repo) and writes `data/opensim/hip-muscles.json`; rerun if the hip muscle set changes
- `tools/opensim_export.py`: run locally with OpenSim (installed: `C:\Users\Erik\miniforge3\envs\opensim\python.exe -I tools/opensim_export.py model.osim out.json`): exports leg-muscle moment arms and active/passive force on hip × knee, knee × ankle and hip flexion × adduction grids. `tools/hip-force.mjs` merges the hip grids into `data/opensim/hip-muscles.json`; `tools/opensim_arm_check.py` the elbow checks with Arm26; `tools/opensim_shoulder_check.py` the shoulder with MoBL-ARMS (non-commercial: docs only); `tools/opensim_hand_check.py` does the hand and wrist checks with the ARMS model (non-commercial licence: allowed in the app's data (edge-lift 3D hand, pinch lift), but every place that uses it must say "non-commercial use only" in its JSON and docs); `tools/opensim-check.mjs export.json` compares the leg exercises' strength curves, two-joint corrections and muscle weights with the model (results in docs/model-limits.md). Not part of the site or the tests
- Links: `#ex=…&v=…&kg=…` plus `cmp`, `px`/`py` (pulley), `pl` (placement), `hand`, `cam` (2d / 3d / side / front / top)
- `tests/*.test.mjs`: `npm test` (node --test)
- Uploaded papers are read locally and removed from the repo afterwards (copyright); never commit PDFs

## Conventions
- Coordinates: base-joint origin, metres, in the exercise's frame: `side` (x forward, y towards the head), `front` (x out to the side, y towards the head), `top` (x out to the side, y forward). Gravity is per variant in that frame. Angles in degrees; positive joint torque = resists the lift.
- Physics changes need a test that checks a hand-computable case (e.g. m·g·L·sin θ). For multi-joint solvers, also check equilibrium (the same torque from both sides of a joint, reactions that add up to the weight).
- Curated numbers (strength curves, muscle weights, modifiers) are estimates. Never present them as measured. Keep or add a `source`/`note`, and never invent citations; write `TODO` if no source has been checked. A new paper cited in a `source` also needs an entry in `data/references.json` (a test checks both ways).
- wger content is CC-BY-SA: keep the attribution visible. Render wger descriptions as text only (no `innerHTML`).
- Test mobile width (375 px): no horizontal scroll, touch-sized controls.
- Run locally: `npm start` (port 8080), then check the browser console for errors.
